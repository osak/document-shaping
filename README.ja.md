# Document Shaping

[English](README.md)

Document Shaping は、設計書などの正式な文書や、明示的に依頼された技術文書を、読み手が必要とする情報に合わせて構成するための AI エージェント向けスキルです。何を先に伝え、どこを詳しく説明し、何を要約・参照・省略するかを考えます。

## 使いどころ

設計書、仕様書、アーキテクチャ決定記録（ADR）、実装計画、レビュー資料、継続的に参照するドキュメントの作成や改訂を依頼するときに使えます。読み手を意識したコードコメントや、背景を含む技術解説にも使えます。

## スキルの動作

読者が持つ前提知識、作業の経緯をどこまで共有しているか、どれくらい時間を置いて読むか、読者の目的、文書を使い続ける期間を踏まえて、何を先に示し、どこまで背景を補うかを決めます。概念は読者に通じる用語で説明し、コードの特定・変更・検証に必要な箇所では、実装上の正確な名前を示します。

一部の改訂では、周囲の構成を保ちながら依頼された箇所を整えます。新規作成や大幅な改訂では、情報を整理し、文書全体の構成を読者の視点で見直します。執筆時の指示は、その指示自体が文書の題材である場合を除き、成果物には含めません。依頼に応じて、構成を決めた理由も説明します。

## エージェントで使う

作業場所にリポジトリをクローンします。

```sh
git clone https://github.com/osak/document-shaping.git
```

`document-shaping` フォルダを、使っているエージェントのスキルディレクトリに置きます。スラッシュコマンドでスキルを呼び出せるエージェントなら、`/document-shaping` に続けて依頼を書きます。`document-shaping/SKILL.md` を読んでもらってから同じ内容を頼むこともできます。

### 読者のペルソナを指定する

ペルソナとは、できあがった文書を誰がどう使うかを表した読者像です。「設計をレビューするチーム向け」の一言でも頼めます。読み手が具体的に決まっているなら、すでに知っていることや、文書を読んで何をしたいのかも添えてみてください。短い依頼では、エージェントが文書の種類や渡した資料から読み手の前提を補います。

### レビュー担当者向けの設計書

**短く頼むなら**

```text
/document-shaping 添付のメモを、レビューするチーム向けの設計書にまとめて。
```

**もう少し詳しく頼むなら**

```text
/document-shaping 添付したキューの再試行メモから、次のレビュー用の設計書を書いて。
読むのは、キューには詳しくて、この提案を初めて読むエンジニア。
変更を進めるか決められるように、今の問題と提案のリスクを先にまとめて。
```

### 将来の保守担当者向けの部分改訂

**短く頼むなら**

```text
/document-shaping 添付のメモをもとに、運用ガイドの再試行ポリシーを次の担当者向けに直して。
```

**もう少し詳しく頼むなら**

```text
/document-shaping 添付の決定メモをもとに、運用ガイドの「再試行ポリシー」節だけ直して。
読むのは、数か月後にキューの運用を引き継ぐ人。
再試行に上限がある理由と、変更前に確認することがガイドだけでわかると助かる。
```

### AI エージェント向けの実装計画

**短く頼むなら**

```text
/document-shaping 添付の仕様を、コーディングエージェント向けの実装計画にして。
```

**もう少し詳しく頼むなら**

```text
/document-shaping 添付の再試行仕様を、別のコーディングエージェントに渡す実装計画にして。
そのエージェントはリポジトリと計画を見て作業する想定。
どこを変えて、どう動作を確かめるかがわかるように書いて。
```

### カスタマーサポート向けの切り替えガイド

**短く頼むなら**

```text
/document-shaping 添付のリリースメモから、サポートチーム向けのガイドを書いて。
```

**もう少し詳しく頼むなら**

```text
/document-shaping 添付のリリースメモを、切り替え直後にサポートチームが使うガイドにして。
読むのは、普段の問い合わせ対応には慣れている担当者。
お客さんから見て何が変わるか、問い合わせが来たときに何を確認すればいいかをまとめて。
```

## リポジトリの構成

| ファイル | 内容 |
| --- | --- |
| [SKILL.md](SKILL.md) | スキルを適用するエージェント向けの指示一式。 |
| [DESIGN.md](DESIGN.md) | 設計の理由と、スキルを保守・拡張する際の原則。 |
| [LICENSE](LICENSE) | 再配布の条件を含む zlib ライセンス。 |

スキルの動作を変えるときは、`SKILL.md` だけで適用できる状態を保ち、変更の理由を `DESIGN.md` に記録してください。適用範囲を保ったまま、部分改訂と文書全体の作成の両方で意図どおりに機能するか確認してください。
